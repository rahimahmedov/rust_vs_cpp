     Plan: Rust vs C++ Ownership & Borrowing Educational Binaries

     Context

     Create two self-contained educational binaries — one in Rust, one in C++ —
     that teach ownership and borrowing/reference concepts through annotated,
     runnable sample code. Each program prints section-by-section output that
     doubles as documentation. The project directory is currently empty.

     Project Layout

     rust_vs_cpp/
     ├── Makefile                        # top-level: builds and runs both
     programs
     ├── rust/
     │   ├── Cargo.toml
     │   └── src/
     │       └── main.rs                 # ~250 lines, single file
     └── cpp/
         └── ownership_demo.cpp          # ~250 lines, single file, C++17

     Single-file binaries (no modules/headers) so a learner reads top-to-bottom
     without navigation.

     ---
     Five Sections (both programs, same structure)

     Each section prints a banner === Section N: ... === then annotated output.

     ┌─────┬────────────┬─────────────────────┬───────────────────────────────┐
     │  #  │   Topic    │  Key Rust Pattern   │        Key C++ Analog         │
     ├─────┼────────────┼─────────────────────┼───────────────────────────────┤
     │ 1   │ Ownership  │ let s2 = s1 moves,  │ std::move(p1) leaves p1 null  │
     │     │ & Move     │ s1 gone             │                               │
     ├─────┼────────────┼─────────────────────┼───────────────────────────────┤
     │     │            │ i32 is Copy, String │ int copies; std::string       │
     │ 2   │ Copy vs    │  moves; .clone()    │ copies by default; MoveOnly   │
     │     │ Move types │ for deep copy       │ struct (copy-deleted) shows   │
     │     │            │                     │ move-only                     │
     ├─────┼────────────┼─────────────────────┼───────────────────────────────┤
     │     │            │ Multiple &s         │                               │
     │ 3   │ Shared /   │ coexist; function   │ const std::string& param;     │
     │     │ const refs │ takes &String       │ multiple const refs fine      │
     │     │            │ without owning      │                               │
     ├─────┼────────────┼─────────────────────┼───────────────────────────────┤
     │     │            │ One &mut s at a     │ std::string&; C++ allows      │
     │ 4   │ Mutable    │ time; mix with &s   │ multiple mutable refs         │
     │     │ refs       │ forbidden (shown as │ (explicitly contrasted)       │
     │     │            │  comment)           │                               │
     ├─────┼────────────┼─────────────────────┼───────────────────────────────┤
     │     │            │ impl Drop, nested   │ ~Resource() destructor, same  │
     │ 5   │ RAII /     │ scopes show LIFO    │ nested demo,                  │
     │     │ Drop       │ order, drop(early)  │ unique_ptr.reset() for early  │
     │     │            │                     │ release                       │
     └─────┴────────────┴─────────────────────┴───────────────────────────────┘

     Intentional compile errors (use-after-move, conflicting borrows) are placed
      inside /* COMPILE ERROR: ... */ block comments — programs compile cleanly,
      learner can uncomment to see the error.

     ---
     Build & Run

     Rust

     cd rust && cargo build --release   # binary:

     C++ (clang++ 17, Apple platform)

     ./cpp/ownership_demo

     Top-level Makefile targets

     - make all — builds both (does NOT run)
     - make run-rust / make run-cpp — build + run
     - make clean
